# interview 6 — quick-lane-tripwire

## A1 [who]
- asked: the agent or human who made the change, as intake.md's route line already says — the engine reads the sha, not the author
- if wrong: cost if wrong: a quick line filed by a reviewer for someone else's commit is inspected the same way, which is the point
- answered: confirm

## A2 [which]
- asked: OPEN and FROZEN Tasks only — a done task's scope is history, an unfrozen task's scope is a draft nobody sealed
- if wrong: cost if wrong: a quick commit into a task's scope the day before its freeze is not refused; the freeze's own receipt freshness catches the moved blob
- answered: confirm

## A3 [when]
- asked: both — `add locate` before (skill) and `learn` after (engine) — because the engine sees nothing until the bundle is written, and a refusal after the commit still names the task to create before the branch merges
- if wrong: cost if wrong: a refused commit stays in the branch history; the refusal names the fix, and the direct lane's commit is the author's to amend
- answered: confirm

## A4 [absent]
- asked: no sensitive floor — only open scopes are matched — and an `index.md` with no key the same
- if wrong: cost if wrong: a bundle that never declared sensitive paths gets no sensitivity tripwire, which is what it declared
- answered: confirm

## A5 [order]
- asked: that they CANNOT both match — M1's floor stands down on a path some node already scopes, and the owner half fires only on a path a node scopes, so the two are disjoint by construction and a both-matching path is named by the OWNER, with `--evidence <cid>` as a route the author can take; the code keeps the floor first so the order stays right if either condition ever widens
- if wrong: cost if wrong: a path that is both is reported by its owner rather than its pattern, which is the more actionable of the two
- answered: confirm

## A6 [experience]
- asked: the refusal to name the path, the reason (the pattern or the task) and the exact `add new Task` line with the path as `--scope`, and to say so when the path arrived by MERGE, because that one is likely not the author's change
- if wrong: cost if wrong: an author meets a floor refusal on a commit they merged rather than wrote; the refusal says which, and the owner half still reads the `quick:` line alone
- answered: confirm

## A7 [which]
- asked: intake.md's Quick step alone — the one file the direct lane actually opens — not verify.md and not the book, because a lane that skips ceremony reads exactly one page
- if wrong: cost if wrong: an author who never opens intake.md meets the refusal at the learn line instead, which is the tripwire working late
- answered: confirm

## A8 [which]
- asked: every one — not a repo, an unresolvable sha, a git binary that is missing or errors — because the direct lane's one bundle write must never be lost to the engine's own inability to look (R:LANEBLOCKED)
- if wrong: cost if wrong: a quick lesson about a sensitive path is recorded in a tree the engine cannot read; the next `doctor` still sees the lesson
- answered: confirm

## A9 [when]
- asked: it at `learn`, after the lesson's own grammar is accepted and before anything is written, so a refused quick line writes nothing at all
- if wrong: cost if wrong: none; a refusal that half-wrote would be the partial-merge shape the engine forbids elsewhere
- answered: confirm

## A10 [absent]
- asked: both as 'nothing matches' — the tripwire is a floor check, not a default-deny
- if wrong: cost if wrong: a bundle that declares no sensitive paths gets no protection from this rung, which is what declaring none means
- answered: confirm

## A11 [order]
- asked: sensitive paths FIRST (the floor outranks an owner) and the doc landing in the source tree and mirrored, never edited per-tree
- if wrong: cost if wrong: a path that is both sensitive and owned is reported as sensitive, which is the higher answer
