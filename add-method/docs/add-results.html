We asked Claude Code to fix 300 real bugs from popular open-source projects — once on its own, and once with the ADD skill installed. Here is what changed, and what it cost.

Claude Code on its own Claude Code + ADD
1 · THE FIX

Did the bug actually get fixed?

Each fix was checked by the project's own hidden tests — the ones its maintainers wrote. The AI never saw them.

A gap of this size is likely real, but it is not proven: with 300 bugs, a difference this small could still be luck. The honest reading is "at least as good, probably a little better."

2 · CHECKING ITS OWN WORK

Did it run the tests before handing the fix back?

Every dot is one bug. A filled dot means the AI ran the project's tests and saw them pass before it said "done".

3 · LEAVING A TEST BEHIND

Did the fix come with a test?

A test shipped with the fix proves what "fixed" means — and stops the same bug from quietly coming back later.

Almost every ADD fix carries its own test. On its own, the AI rarely writes one.

4 · WHEN THE REQUEST IS UNCLEAR

What happens when you forget to say something?

In a smaller test we asked for a booking app but never said who is allowed to cancel a booking. Real requests are full of gaps like this.

On its own

  • Let anyone cancel anyone's booking.
  • Did not mention it made that choice.

With ADD

  • Chose the safe reading: only the owner may cancel.
  • Wrote the choice down, so you can check it in one line.

5 · THE PRICE

What does it cost?

ADD costs more. Most of the extra goes on running tests — that is the checking you saw in step 2.

6 · ONE SETTING MATTERS

Give it enough effort to read its own instructions

claude --effort medium
WHICH SHOULD YOU USE?

Pick by what happens to the code next

Claude Code on its own

  • Throwaway scripts and quick experiments.
  • Nobody will review or maintain the code.
  • Speed and price matter most.

Claude Code + ADD

  • Code you will keep, change, or share with a team.
  • You want to see that it was checked, not just told.
  • Your request might have gaps the AI has to fill.
THE FINE PRINT

What we have not measured yet

  • Whether ADD saves you review time. Every run was automatic, with no person in the loop. A timed review study is in progress; until then this is not measured.
  • Brand-new bugs. These 300 bugs are public and older than the AI, so it may have seen some of the real fixes before.
  • Repeat runs. Each side fixed each bug once. Another run would move the numbers a little.
