# Impeccable design context — AIDD-Book / ADD

## Design Context

### Users
Developers and tech leads evaluating whether to trust ADD 3.0 with AI-driven builds.
Context: reading docs/blog during work hours, deciding on adoption. Skeptical of AI
marketing; convinced by terminal output, numbers, and admitted limits.

### Brand Personality
Measured · unforgiving · honest. The product is a notary: it records receipts and
refuses lies. The voice never rounds up, states its own bugs, and leads with evidence.

### Aesthetic Direction
"The notary's ledger": paper-and-ink audit ledger with rubber-stamp verdicts. Light
theme default (docs-adjacent daytime reading), full dark support. Hairline ledger
rules, generous margins, asymmetric editorial layout. Refusal-red and receipt-green
appear ONLY as data semantics, never decoration. No glassmorphism, no neon-on-dark,
no gradient text, no side-stripe callouts, no icon-topped card grids.
Constraint: pages may ship as claude.ai Artifacts (strict CSP) — no external fonts or
libraries; system font stacks (Iowan Old Style/Palatino serif display, ui-monospace
data) and hand-rolled SVG/CSS charts only.

### Design Principles
1. Every number on the page must trace to a measured artifact — charts are evidence,
   never decoration (no sparkline garnish).
2. Verdicts read as stamps: full-bordered, inked, sparse.
3. The honest limit gets equal visual weight to the win.
4. Real terminal output is a first-class visual element.
5. One accent moment per section; paper carries the rest.
