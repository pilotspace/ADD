# Pilot — ADD 4.0 vs ADD 3.7.0 (2026-09-28)

Two arms, same model (`claude-sonnet-5 --effort medium`), same harness, one rep per cell:
`add-3x` (release/3.7.0 @ fba54456, the Python engine) and `add-4` (feat/add-4-skill-only @
045bf34b, one skill, no engine). Workloads: `wm1` (a feature build) and `amb1` (seven planted
ambiguities). Run artifacts: `benchmark/runs-4v3-2026-09-28/` (gitignored).

**n = 1 per cell. Past reps of the same arm varied ~2× in cost. Nothing here is significant;
it is a pilot, not a result.**

| oracle pass rate | 1.00 | 1.00 | 1.00 | 1.00 |
| requirement coverage | 1.00 | 1.00 | 1.00 | 1.00 |
| ambiguities guessed right (of 7) | — | — | 4 | 5 |

What the pilot supports:
- **Quality held without the engine.** Both 4.0 runs shipped everything the oracle checks, and
  4.0 guessed one more planted ambiguity right (cancel authority: owner-only).
- **Adherence held without enforcement — when the prompt walks the loop.** Both 4.0 runs wrote a
  task file, ran failing checks first, sealed with a `freeze(` commit, kept the seal intact, and
  closed with a `verify(` commit and an EVIDENCE verdict. The 3.7 wm1 run sealed after a test run
  that failed only on an import error — red for the wrong reason, which its engine did not catch.
- **No clear cost win yet.** Cost was level on amb1 and 21% higher for 4.0 on wm1; total tokens
  were level on wm1 and 42% lower for 4.0 on amb1. 4.0 was slower in wall time on both.

What it does not support: any claim that 4.0 is cheaper or better. Engine calls were cheap in
these short runs, so removing 36 of them did not move cost. The earlier 3.x cost gap
(`BENCHMARK.md`) was measured over longer, longitudinal workloads where context accumulates.

Caveats: the `add-skill` wrapper spells out the loop step by step (as `add-loop` does for 3.x),
so this measures the method under a guiding prompt, not unprompted adherence. Ceilings are not
enforced by the runner. The 3.x control differs from historical runs (the `brief` step, the git
baseline), so it is not comparable with older records.

Census fix found by this pilot: `loop_census.red_first` missed colored unittest output (ANSI codes
broke `FAILED (failures=` and the `\bAssertionError\b` boundary), under-reporting 4.0 amb1 as
not red-first. Fixed with a test from the real output; the table uses the corrected census.

## Round 2 — floor and the turn budget

**Floor.** `vanilla` (no method) on wm1: 14 turns · 420k tokens · $0.40 · oracle 1.00. On amb1 it
stopped after 4 turns and shipped nothing (oracle 0.00), so amb1 has no valid floor.

**Anatomy.** Every arm starts at ~46k tokens of context before doing anything (the agent session
itself), and total tokens ≈ turns × context. The method's cost is therefore its extra TURNS, not
its bytes. 4.0 v1 ran 7 turns over the floor on wm1: a read of `references/format.md`, separate
red-run / seal / evidence turns, and fix-ups. 3.7 chained its 36 engine calls into ~12 commands.

**Change (0b9bdd86).** Task template inline in SKILL.md; orient in one command; a `## Turns` rule:
Direction = two turns (write task + tests, then one command runs the checks and commits the
freeze), batched build, Verify = two turns. Then a stub hint: write `NotImplementedError` stubs
with the checks so the first red is for the right reason.

| turns | 15 | 16 | 18 | 27 |

Against 4.0 v1: wm1 turns 21 → 15.5, tokens 680k → ~490k (−28%), cost $0.50 → $0.42; within 16%
of the no-method floor on tokens and at the floor on cost. amb1 tokens 656k → ~560k (−15%),
cost $0.56 → $0.46, against 3.7's 1,135k / $0.57. Quality unchanged. One lapse in four: wm1 r1
sealed after an import-error red — the stub hint added after this round targets exactly that.

Census fixes from this round (each with a test from the real output): a test run inside the
seal command counts toward red-first; only the task file and the files its CHECKS name are
sealed (PROJECT.md or a .pyc riding in the freeze commit is not); a stub's NotImplementedError is
a right-reason red. Two runs per cell is still not significant.
