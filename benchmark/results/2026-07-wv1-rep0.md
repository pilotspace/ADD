## Honest-outcome findings (n=1 — treat as direction, not conclusion)

1. **WV1 does not differentiate trust at n=1.** All four arms held every floor
   (fidelity, regression-0, no tampering, own green suite) on clean state. The one
   real fidelity miss all campaign: **add (branch) wm2 cancellation window** (0.80 —
   reproduces on clean state; add-main got it right, so it's a branch-flow regression
   to chase, not an ADD-flow property).
2. **Cost separates hard**: vanilla $3.07 / spec-kit $3.43 vs add $9.30 / add-main
   $13.94 — the ceremony gap is 2.7–4.5× on this friendly workload, consistent with v1.
3. **Branch vs main control**: −33% cost (9.30 vs 13.94) at equal trust except the
   wm2 miss above. The branch's leaning is real but bought one fidelity slip this rep.
4. **Un-metered robustness differentiator, found during rescore**: at wm3, apps
   inherit stored bookings written under the wm2 shape. **add-main migrated its
   stored data; vanilla handled it; add and spec-kit both CRASH (KeyError
   'end_time') serving requests over legacy rows.** Not scored (the workload never
   demands a data migration — probe-injected state made it un-scoreable this rep),
   but it is exactly the trust-dimension WV2+ should probe deliberately.
