# ADD 2.0 remeasure + context campaigns — add vs spec-kit across three session modes (2026-07-18, REVISED)

**REVISION NOTICE.** The first edition of this report (commit `52412c36`) claimed a
spec-kit evolution collapse (wm2–3 coverage .20/.25) from the 3-WM fresh campaign.
Extending to six milestones surfaced **three meter defects** whose fixes refute that
claim — the collapse was scoring pollution, not method failure. This edition is the
corrected record; every number below was produced by the fixed meter
(`cb001a75` room-adaptive survivors · `fd7ccbf7` conftest collision ·
tempdir-isolation + probe-day fixes in this commit). Honest receipts beat dramatic
ones; the retractions are listed explicitly at the end.

Campaign: workload wm1→wm6 (CRUD → business rules + auth → breaking shape change →
filters/pagination/recurring → rooms cross-cutting refactor → correctness
hardening) · pinned meter (sonnet-5 / effort medium) · deterministic probes, no LLM
judge · ADD 2.0.0 from this checkout · spec-kit v0.12.5 · n=1 per cell.

## Three session modes

- **fresh** — new conversation + new copied workspace per WM (per-WM frozen
  snapshots; the classic control).
- **persist** — new conversation per WM in ONE persistent project folder, setup at
  WM1 only. The realistic day-to-day shape: one repo, resume anytime.
- **conv** (conversation-carry, ARCHIVED) — one continuing conversation
  (`--continue`) + one folder. Measured once, then removed from the harness by user
  decision; kept here as the context-rot experiment.

## Finding 1 — the mode is the hazard, not the method (context rot, causal)

In fresh and persist modes BOTH methods hold every floor across six milestones,
including the cross-cutting rooms refactor. In conversation-carry mode both decay
identically: at wm1 the agent shaped `GET /bookings` as an `{"bookings": [...]}`
envelope (the spec requires a bare list — verified in the workspace code, not just
probes), and the continued conversation **never revisited that choice across five
more milestones** — while actively editing that endpoint for auth, filters, and the
rooms refactor. It even built wm6's brand-new hardening features to 1.0 coverage
*while still failing a third of the earlier milestones' invariants*. Fresh sessions
re-derived the listing shape from the spec correctly in 4 of 4 arm-runs.

**Corrected claim: context rot is real, measurable, and lives in the conversation,
not the method.** Restart-from-disk (any disk: ADD's board or spec-kit's specs)
eliminated it in every measured cell. What a method must supply is state good
enough to restart from — both methods' state passed that bar on this workload.

## Finding 2 — cost, the honest version

At equal measured trust (all floors 1.0), fresh spec-kit is cheaper: $10.05 vs
$17.51 per 6-WM rep ($1.68 vs $2.92 per milestone). In persist mode the gap
narrows: spec-kit $8.50/6 WMs; add $8.60 through 4 WMs (~$13–15 projected). The
defensible ADD 2.0 cost claim is against its OWN lineage: 1.x measured $4.65–13.94
per trusted feature on this meter family; 2.0 runs $2.15–2.92 — the ceremony tax
was cut roughly 3–5× while keeping the discipline.

## Finding 3 — what this workload cannot differentiate

A sonnet-5-class agent with any structured spec flow passes this single-app CRUD
workload's floors in restart modes. This matches WV1/WV2 (2026-07-10): on friendly
workloads, trust floors don't separate the flows at n=1 — cost does. ADD's
distinctive machinery (frozen-contract tamper tripwire, security HARD-STOP,
scope fences) is insurance whose value must be measured where violations actually
tempt: hostile changes (WV2 found none at this temptation strength), weaker
models, messier multi-component repos, longer horizons. The hv hard-cases track
exists for exactly this; it has not yet run against real arms.

## Meter defects found by this campaign (all fixed + guard-tested)

1. **Missing survivors wm3–5** — wm4+ regression scoring refused to run
   (`aa8ac65d`); survivors authored room-adaptively.
2. **wm2 survivors not room-adaptive** — 3/13 false regressions at wm5+ on correct
   apps (`cb001a75`).
3. **conftest module collision** — wm4-6 lacked package `__init__.py`; joint
   survivor spawns crashed (`fd7ccbf7`).
4. **Tempdir store pollution (the big one)** — a spec-kit-arm app persisted at
   `$TMPDIR/app_bookings.json`, outside the workspace; ONE global temp file
   accumulated bookings across every probe/suite/run/campaign. `running_app` now
   hands each boot a fresh private TMPDIR. This defect manufactured the entire
   "spec-kit evolution collapse" of the first edition.
5. **wm4 pagination probe day-collision** — fixed 2026-09 windows collided with the
   filter probe's bookings (409s); re-dated + window-scoped.
6. **Session-mode records are era-scorable only in-campaign** — no per-WM workspace
   snapshot exists (only test snapshots), so post-hoc rescores hit the end-state
   app. Two records repaired/annotated; follow-up: snapshot workspaces per WM in
   session modes.
