# ADD 2.0 remeasure + context-rot campaign — add vs spec-kit, fresh vs continue (2026-07-18)

Campaign: in-repo `benchmark/runs` (fresh control) + `benchmark/runs-session`
(continue mode) · pinned meter (sonnet-5 / effort medium, model stamped per record) ·
workload wm1→wm2→wm3 (CRUD → business rules + auth → breaking-change refactor with
regression bait) · deterministic scoring only (no LLM judge).
Method under test: **ADD 2.0.0** (`pilotspace-add==2.0.0` installed editable from this
checkout; resolved pins `f3f3dd6b`/`015048d4` differ only in `benchmark/` — the
engine bytes are identical across all records). spec-kit arm: v0.12.5.

Two questions:
1. **Cost target** — is ADD 2.0 ≤2× spec-kit per rep (1.x measured ~2.7×)?
2. **Context rot (NEW)** — what happens when ONE agent conversation carries all
   three milestones (`--session-mode continue`: one persistent workspace, `--continue`
   argv from wm2 on) versus the fresh-per-WM control?

## Fresh control (one conversation per WM, board carried by copy)

| arm | wm1 | wm2 | wm3 | rep cost | rot slope |
|---|---|---|---|---|---|
| **add** | 1.00 · $2.46 | 1.00 · $2.98 | 1.00 · $1.17 | **$6.61** | 0.0 |
| **spec-kit** | 1.00 · $1.21 | cov .20 · orc .20 · reg .33 · weak 6 · $1.29 | cov .25 · orc .50 · reg .43 · weak 2 · $1.40 | **$3.90** | −0.375 |

(cells = requirement_coverage; orc = oracle_pass_rate, reg = regression_rate,
weak = tests_weakened. add: every floor 1.0, zero regressions, zero weakening.)

**Cost target MET: add = 1.7× spec-kit** ($6.61 vs $3.90), down from ~2.7× on 1.x —
and the raw ratio flatters spec-kit. Its wm2 missed ALL four business-rule
requirements (ownership-403, double-booking-409, cancellation-window,
tenant-isolation) while weakening six carried tests, and wm3 broke 43% of earlier
oracles. Per **trusted** WM (all floors 1.0): add $6.61/3 = **$2.20**, spec-kit
$3.90/1 = **$3.90** — ADD 2.0 is now the *cheaper* flow per unit of trusted work
(1.x add-main measured $13.94 per trusted feature).

### The rot signature: one early deviation, never re-examined

Every continue-mode miss traces to **one defect per arm, the SAME defect in both
arms**: at wm1 the agent shaped `GET /bookings` as an `{"bookings": [...]}` envelope
(the frozen checklist requires a bare JSON list → `R-get-list` red), and the
continued conversation **never revisited that choice again** — wm2's
`R-tenant-isolation` and wm3's `R-list-no-duration` are the same envelope failing
list-shaped probes, plus the matching earlier-WM oracles re-failing as "regressions".
Both arms actively edited the list endpoint in wm2/wm3 (auth scoping, end_time
reshape) without ever re-deriving its response shape from the spec: the
conversation's memory of its own earlier design outweighed the written requirement.
Fresh-mode agents re-read the board each session and produced the bare list 2/2.

### Reading the two modes together

- **Continue mode erases the method difference.** add and spec-kit post
  *identical* per-WM trajectories (same misses, same regressions) — once
  conversation memory dominates, the flow's on-disk discipline stops mattering.
- **Fresh mode is where method quality shows.** add held 1.0 across the evolution
  WMs because its board (frozen contract + red suite + PLAN.md) IS the context; a
  fresh session loses nothing. spec-kit's fresh sessions collapsed on wm2/wm3
  (cov .20/.25) — its artifacts didn't carry enough intent, and *continue mode
  actually rescued it* (cov .80/.75) by substituting conversation memory for board
  memory.
- Net: **externalized context beats accumulated context** — fresh-add (1.0 flat) >
  continue-either (~.92→.75 decay) > fresh-spec-kit (collapse). ADD 2.0's design
  premise — externalize everything, restart clean per milestone — is the measured
  best case of the four cells.

## Caveats (n=1 per cell — direction, not conclusion)

- wm1 fresh-vs-continue conditions are statistically identical (no `--continue`
  at wm1); the envelope-vs-bare-list split there is run variance. The rot claim
  rests on the *persistence*: two further milestones touching the same endpoint
  in-conversation never corrected it, while fresh sessions never introduced it.
- Both continue arms landing the identical envelope deviation is consistent with a
  model-level prior; more reps would separate prior from coincidence.
- spec-kit's fresh wm2/wm3 collapse is one rep; its historical multi-WM runs
  (2026-07-08 campaign) showed the same evolution weakness at wm2+.

## Verdict for the 2.0 release

- **≤2× spec-kit: MET (1.7×)**; per trusted WM, add is cheaper outright ($2.20 vs
  $3.90).
- **Trust floors: add fresh = 1.0 across all three WMs**, zero regressions, zero
  test-weakening — the 2.0 lean lane (3-call walk, one freeze, PLAN.md) lost none
  of 1.x's discipline while cutting ~½ the 1.x rep cost.
- **Context-rot capability shipped** (`--session-mode continue`, distinct
  `--runs-root`): first campaign shows decay −0.083 cov/WM in-conversation vs 0.0
  on the board-carried control; keep continue-mode as the standing rot probe for
  future method changes.
