One page for every 4.0 number the READMEs, the book, the value page and the flow page quote. It
consolidates four pilot rounds; each figure below links back to the round it came from.

- Round 5 — [PILOT-4v3-2026-09-30-r5.md](../PILOT-4v3-2026-09-30-r5.md)
- Round 6, on Sonnet 5.5 — [PILOT-4v3-2026-09-30-r6.md](../PILOT-4v3-2026-09-30-r6.md) ([below](#round-6--the-same-skill-on-sonnet-55))

**Setup.** Arms: `vanilla` (Claude Code, prompt in, code out) and `add-4` (the same Claude Code with
the ADD 4.0 skill installed). Model pinned: `claude-sonnet-5 --effort medium` in rounds 3–5,
`claude-sonnet-5-5 --effort medium` in round 6. Workloads: **wm1** — a
booking REST API and CLI built from scratch; **amb1** — the same service from a spec with a planted
contradiction and six silent gaps. **n = 3 per arm per workload per round; rounds 4 and 5 ran on the
same day.** Not significant — direction, not proof.

**Quality measures** (`benchmark/quality.py`): held-out edge suite (19 cases for wm1, 14 for amb1,
never shown to the agent); mutation score (24 seeded bugs — the share the agent's own tests catch);
tests written; whether the test count the agent claims matches a fresh rerun.

## Disclosures — read before quoting

- **"Vanilla" is not bare Claude Code.** The harness passes no `--setting-sources`, so both arms load
  the operator's `~/.claude` config (a CLAUDE.md asking for red/green TDD, plugin workflow rules). Every
  delta is ADD over an already disciplined setup.
- **The correctness oracle is saturated.** Both arms pass it in almost every run (below), so it
  cannot show a correctness gain in either direction on these workloads.
- **Reruns.** Nine runs died when the CLI account changed mid-round (a 403, a logout) or the session restarted; they were
  set aside and rerun at the same commit the same day. One run's first attempt was cut off with no
  result event: its cost ($2.02) adds 4.58M tokens at the sibling runs' $0.38/M — an estimate.
- **The skill changed between rounds 4 and 5** (task `value-over-ceremony`): rows marked r4 measure
  the skill at 0ec8b2d5, rows marked r5 the skill at 82e4d0a0, which is the one merged in 4.0.

## Which rules changed behaviour (ADD, r4 → r5)

| rule added in `value-over-ceremony` | r4 | r5 | transferred? |
|---|---|---|---|
| checks send inputs the way a real caller does (malformed body, timestamp offsets) | malformed-body crash in 4 of 6 runs | 0 of 6 | **yes** — partly taught: the edge suite tests the body half |
| a silence about who may act takes the least-privilege reading | owner-only cancel in 0 of 3 | 1 of 3 | weak |
| the report lists the costliest guess first | never | 2 of 6 | weak |
| Direction in three turns (batched setup and writes) | 21 messages (wm1) · 20 (amb1) | 23 (wm1) · 14 (amb1) | no on wm1 |

**The lesson:** a rule changes behaviour when it names an artifact the model must write — a check, a
`covers:` line. Advice about how to think, order or batch mostly does not.

**Saturation.** On Sonnet 5.5 both workloads saturate: vanilla ties ADD on every held-out edge case,
mutation scores sit within noise, and vanilla wrote tests in 6 of 6 runs. What still separates the
arms is how the silences in a spec get read, and whether the reading is written down.

**Across rounds.** On who may cancel someone else's booking, vanilla read it as owner-only in 0 of
8 amb1 runs across rounds 4–6 — every run let any caller cancel. ADD chose owner-only in 0 of 3 (round 4, before the
least-privilege rule), 1 of 3 (round 5) and 3 of 3 (round 6). No Sonnet run of either arm halted in
round 6: every amb1 run on disk now reads vanilla 2 of 10 halted, ADD 0 of 16. Claimed test counts
matched a rerun in 33 of 33 ADD runs across rounds 3–6.

**The model moved the cost more than the method did.** The same ADD skill cost $1.67 → $0.52 a run
on wm1 and $1.31 → $0.68 on amb1 from Sonnet 5 to Sonnet 5.5, and its Direction beat fell from 4.1
min to 1.1 min (wm1) and 1.7 min (amb1).

## Context rot — the earlier, 2.0-era measurement

Kept here because the value page quotes it: over six evolving milestones with the same pinned model,
one long conversation's requirement coverage fell from 0.92 to 0.75 and never recovered; a fresh session
per milestone resuming from disk held 1.0 across all six (n = 1 per arm, ADD 2.0.0 —
[report](./2026-07-add-2.0-remeasure.md)).
